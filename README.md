# Pipeline Detective

CPU 파이프라인에서 **값이 언제 준비되고, 언제 읽히며, 언제 레지스터에 기록되는지** 직접 판단하는 학습용 디버깅 퍼즐입니다. 짧은 RISC-V 어셈블리 예시를 보고 NOP·stall·flush 개수를 고른 뒤, 클록 표와 값 추적으로 선택의 결과를 확인할 수 있습니다.

## 현재 할 수 있는 일

- 네 사건 유형 학습: forwarding 없는 RAW 의존성, ALU forwarding, load-use hazard, taken branch의 flush.
- 각 사건에서 **새 코드 받기**: 레지스터·숫자·독립 명령 수 또는 분기 결정 단계가 달라지는 연습 예시 생성. 예시에 따라 필요한 대기·flush 개수도 달라집니다.
- 정답과 오답의 클록별 파이프라인 배치 비교, 핵심 클록 해설, 레지스터·메모리 값 추적.
- 한국어/영어 전환, 사건 완료 표시, 예시 번호의 브라우저 저장.

## 실행

```bash
cd cpu-debug-puzzles
npm run serve
```

브라우저에서 `http://127.0.0.1:8791/`을 엽니다. 별도 패키지 설치는 필요하지 않습니다. 테스트는 `npm test`로 실행합니다.

## 학습 순서

1. 사건의 조건과 어셈블리 코드를 읽고 0·1·2 중 하나를 선택합니다.
2. **파이프라인 실행** 후 클록을 이동하며 생산 명령과 소비 명령의 위치를 확인합니다.
3. 값 추적에서 EX/MEM의 임시 값과 WB에서 기록된 레지스터 값을 구분합니다.
4. 해설에서 자신의 배치와 정답 배치를 비교합니다. 더 연습하려면 **새 코드 받기**를 누릅니다.

## 코드 구성과 모델 범위

| 파일 | 역할 |
| --- | --- |
| `src/puzzles.js` | 네 사건의 기본 코드·조건·이중 언어 해설 |
| `src/variants.js` | 사건별 새 연습 코드와 그에 맞는 해설 생성 |
| `src/engine.js` | 5단계 IF/ID/EX/MEM/WB 타이밍과 정답·클록 표 계산 |
| `src/valueTrace.js` | 사건별 클록의 레지스터·메모리 값과 임시 결과 추적 |
| `src/explanation.js` | 선택한 답이 빠르거나 과도한 이유 진단 |
| `src/app.js`, `src/style.css` | 화면 상태·상호작용·스타일 |
| `tests/engine.test.js` | 타이밍, 정답, 생성 예시, 값 추적 검증 |

현재 모델은 위 네 사건 유형을 위한 **교육용 5단계 파이프라인 모델**입니다. 모든 RV32I 명령을 실행하는 범용 시뮬레이터나 원본 RTL의 실행 결과를 대체하지 않습니다. 같은 클록에서 WB 쓰기는 ID 읽기 전에 보인다고 가정하며, ALU 값은 EX 뒤, load 값은 MEM 뒤에 forwarding할 수 있습니다. 분기 결정 단계는 각 예시에 표시됩니다.

## 출처와 사용 목적

이 프로젝트는 `devjwk`의 공개 CPU 프로젝트 코드에서 착안한 **비영리 학습용** 자료입니다. 사건 화면의 **관련 원본 RTL** 링크에서 연결된 코드를 확인할 수 있습니다. 생성된 연습 코드는 이 사이트에서 만든 예시이며, 원본 저장소의 코드와 동일하다는 뜻은 아닙니다. 원본 코드와 학교 과제 자료의 권리는 각 권리자에게 있습니다.
